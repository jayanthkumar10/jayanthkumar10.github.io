Cardiac Anomaly Detection

Clinical ML research focused on optimizing for Recall (Sensitivity) over Accuracy to minimize fatal False Negatives. Resulted in a published patent application.

The Research Context

This was a research project conducted at SRM University. The goal was to explore whether standard supervised learning algorithms could improve early-stage cardiac disease detection using aggregated clinical data from multiple sources.

The primary engineering lesson learned here was not about model architecture, but about evaluation metrics.

Engineering Decisions

Optimizing for Recall over Accuracy

The Trap

My initial model optimized for Accuracy, achieving 93%. But the clinical dataset was heavily imbalanced (most patients were healthy). A naive model that simply predicted "healthy" for everyone would score very high accuracy.

The Solution

In clinical ML, a False Negative (telling a sick patient they are healthy) is categorically worse than a False Positive (requiring a healthy patient to take another test). I shifted the evaluation metric entirely to Recall (Sensitivity).

Result: Accuracy dropped by 6%, but Recall increased by 25%. A mathematically worse model, but a clinically correct one.

SMOTE + Custom Thresholding

The Implementation

I applied SMOTE (Synthetic Minority Over-sampling Technique) to balance the training data. More importantly, I dropped the decision threshold of the XGBoost classifier from the default 0.5 down to 0.35.

The Reasoning

Dropping the threshold means the model flags a patient as "at risk" even if it is only 35% confident. This intentionally generates more False Positives to ensure we catch nearly all True Positives.

Implementation Detail: Evaluation Gate

This code block demonstrates how the evaluation logic was explicitly constrained to reject models that had an unacceptable False Negative rate, regardless of their overall accuracy.

evaluation.py Python 
def evaluate_for_clinical_domain(y_true, y_pred_proba, threshold=0.35):
    # Lower threshold: accept more false positives to catch more true positives
    y_pred = (y_pred_proba >= threshold).astype(int)
    tn, fp, fn, tp = confusion_matrix(y_true, y_pred).ravel()

    recall = recall_score(y_true, y_pred)
    
    # In this domain, a high false-negative rate is unacceptable
    if fn > tp * 0.05:
        raise ValueError(f"FN rate too high for clinical use: {fn}/{tp}")

    return {
        "recall": recall, 
        "false_negatives": fn, 
        "false_positives": fp
    }

Lessons Learned

Model evaluation must be grounded in the domain. Standard metrics (Accuracy, F1) are starting points, not conclusions. The same principle applies in modern AI systems—evaluating an LLM on a generic benchmark doesn't tell you if it's right for your specific use case. Domain-constrained evaluation is a discipline I carry into all my LLM work today.
