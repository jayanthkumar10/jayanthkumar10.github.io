Pathlight.ai

Autonomous ATS-Optimized Resume Tailoring Engine · Asynchronous LLM Pipeline with Full Observability

0 Blocking API calls
↗ GitHub
// The Problem

Job applications fail ATS screening not because of candidate quality but because of keyword mismatch. Manual tailoring per job description is O(n) human effort that doesn't scale. The existing tooling required a human in the loop for every single application cycle.

// The Failure State (V1)

Initial architecture: synchronous FastAPI endpoint calling Gemini directly. Under load, Gemini's response time exceeded the HTTP timeout threshold, causing 504s. The entire request chain blocked. Workers starved. No recovery path.

// The Architecture Decision

Introduced Celery + Redis as a durable task queue. FastAPI now accepts the request, enqueues a job, and returns a task ID instantly. The client polls for status. Celery workers execute the LLM call, PDF generation, and S3 upload independently. Zero blocking.

// Observability Layer

Integrated Langfuse via OpenTelemetry to trace every LLM generation: input tokens, output tokens, latency per hop, cost per run. If the primary model (Gemini) fails, the pipeline automatically falls back to OpenRouter. Every fallback is logged.

tasks/resume_tailor.py — Celery task with fallback chain Python 
@celery_app.task(bind=True, max_retries=3, acks_late=True)
def tailor_resume(self, task_id: str, payload: dict):
    # Primary: Gemini Flash 1.5
    try:
        result = gemini_client.generate(payload)
    except GeminiRateLimitError:
        # Automatic fallback to OpenRouter
        result = openrouter_client.generate(payload, model="mistral-7b-instruct")

    # Observability: trace every generation
    langfuse.trace(
        name="resume_tailor", input=payload,
        output=result, metadata={"task_id": task_id}
    )
    pdf_path = render_pdf(result.html)
    redis.set(task_id, {"status": "done", "url": pdf_path})

PulseOps AI

Autonomous Incident Triage & Allocation Engine · Offline-First Multi-Agent Pipeline

<1ms Vector search latency
↗ GitHub
// The Problem

SRE teams suffer from alert fatigue: hundreds of incidents per day, each requiring manual triage, root cause lookup, and on-call assignment. MTTR is inflated not by remediation time but by routing time.

// The Failure State (V1)

Initial build used cloud LLM APIs (GPT-4). During actual network outages — the exact moments when incident management is most critical — the system was entirely unavailable. An AI that fails during failures is useless.

// The Architecture Decision

Rebuilt with local Llama 3.2 via Ollama. Zero network dependency. The vector store is an in-memory TF-IDF engine (pure NumPy), intentionally chosen over FAISS because SRE incident descriptions are keyword-dense — sparse vectors outperform dense embeddings in this domain.

// The Trade-off

Local Llama 3.2 has a smaller context window and lower accuracy than GPT-4. This was acceptable: the Triage Agent uses deterministic scoring matrices, reducing LLM responsibility to structured extraction only. Accuracy-critical reasoning is explicit, not model-dependent.

Cardiac Anomaly Detection

Clinical ML Pipeline Optimizing for Recall over Accuracy · Cost-Sensitive Loss Engineering

96.5% Clinical Recall (sensitivity)
↗ GitHub
// The Problem

In medical ML, a False Negative is a patient sent home to die. Standard model optimization targets Accuracy. A model predicting "Healthy" 100% of the time on an imbalanced clinical dataset achieves 93% accuracy — and kills people.

// The Failure State (V1)

Initial Random Forest model achieved 93% accuracy with a catastrophic False Negative rate. Standard optimization metrics were completely wrong for this domain. The mathematical framework had to be rebuilt from the domain constraint up.

// The Architecture Decision

Replaced Accuracy with Recall as the sole optimization target. Applied SMOTE oversampling to synthetically balance the minority class. Introduced a custom cost-sensitive penalty matrix in XGBoost: False Negatives penalized 10x more than False Positives. This explicit mathematical constraint encoded the clinical domain requirement.

// The Trade-off

Precision dropped from 95% to 89%. In SaaS, this creates user friction. In healthcare, this is legally and ethically mandatory. The decision to sacrifice Precision for Recall was not a model limitation — it was the correct engineering choice for the domain. This nuance became the core of a published patent.

evaluation.py — Clinical viability gate Python 
def evaluate_clinical_viability(y_true, y_pred_proba, threshold=0.35):
    # Lower decision boundary → aggressively catch positives
    y_pred = (y_pred_proba >= threshold).astype(int)
    tn, fp, fn, tp = confusion_matrix(y_true, y_pred).ravel()

    # Hard reject: False Negative rate cannot exceed 5% of True Positives
    if fn > (tp * 0.05):
        raise ClinicalRejectionError(
            f"Model rejected: FN={fn}, TP={tp}. Ratio exceeds clinical threshold."
        )
    return {"recall": recall_score(y_true, y_pred), "false_negatives": fn}

WhatsApp Booking Orchestration

Decoupled Conversational Agent · Business Logic Decoupled from Deployment Cycles via n8n

70% Manual effort eliminated
// The Problem

Administrators spent hours daily copying WhatsApp messages into Google Calendar manually, causing double-bookings and missed appointments. Every new booking intent required a developer code change.

// The Failure State (V1)

Initial architecture: a monolithic Node.js Express app with hundreds of regex matches. Adding a single new intent (e.g., "Cancel booking") required code changes, CI/CD, and a full deployment. Development velocity bottlenecked by coupling.

// The Architecture Decision

Introduced n8n as a visual orchestration layer. Webhook ingestion, intent routing, and Google Calendar API calls moved into n8n's node-based engine. Node.js was relegated to cryptographic validation only. New intents deploy in seconds, not hours.

// The Trade-off

n8n adds ~50ms network overhead. In a high-frequency trading system, fatal. In asynchronous human chat interfaces, imperceptible. The correct engineering call is not "minimize latency always" — it's "minimize latency where it matters." Time-to-deploy for new intents dropped from hours to seconds.

// 02 — ENGINEERING PHILOSOPHY

How I Think

Every AI system I build is designed against these constraints — not as afterthoughts, but as first-class architectural requirements.

⚡
Latency-First Design
Every LLM call is measured. Async by default. Sync only when the UX demands it. P99 budgets enforced at design time.
📡
Observable by Default
Traces, structured logs, and metrics on every agent hop. If I can't measure it, I can't improve it.
🔁
Fallback-Ready
Every external call has a timeout, retry budget, and fallback path. Systems that fail gracefully are production systems.
💰
Cost-Aware Architecture
Token budgets enforced. Cheaper model fallbacks on low-complexity tasks. Inference cost is a product constraint, not an ops detail.
🧪
Eval-Driven Development
Ground-truth evaluations exist before any model swap. "It feels better" is not an evaluation strategy.
👤
Human-in-the-Loop
Escalation paths for low-confidence outputs. AI augments the human; it doesn't remove accountability.
🗄️
Stateless Agents
Shared state lives in Redis or Postgres, never in-process. Any agent instance can pick up any task.
📐
Schema-First Outputs
Structured outputs validated with Pydantic before they leave the LLM boundary. Free-text from models is never trusted raw.
🔒
Offline-Capable
Local inference for sensitive or air-gapped environments. Data privacy is an architectural constraint, not a legal footnote.
🔍
Explainable Reasoning
Reasoning traces surfaced to end users and operators. Black-box AI in enterprise = unacceptable risk.
🔧
Swappable Components
Agents are decoupled. Swap the LLM, the vector store, or the queue without rewriting the orchestration layer.
🚀
Production, Not Demo
Deployed systems, not notebooks. Notebooks are for exploration. Production is the standard.

// 04 — ENGINEERING DECISIONS

Why, Not What

Junior engineers list technologies. Senior engineers explain why they chose them over the alternatives they seriously considered.

FastAPI over Flask
→ Chosen: FastAPI
Why
Native async, Pydantic validation baked in, automatic OpenAPI docs generation.
Alternative
Flask: synchronous by default, requires extensions for validation, no native async.
Tradeoff: steeper learning curve → eliminated tech debt at scale
Redis + Celery over Threading
→ Chosen: Celery + Redis
Why
Durable task queue survives process restarts. Tasks observable. Workers horizontally scalable.
Alternative
asyncio background tasks: in-memory, lost on crash, no retry, no visibility.
Tradeoff: operational overhead → required at production reliability levels
TF-IDF over Dense Embeddings
→ Chosen: TF-IDF (PulseOps RAG)
Why
SRE incident text is keyword-dense and domain-specific. Sparse vectors outperform dense on rare, anomalous tokens like "OOMKilled" or "502 Bad Gateway".
Alternative
FAISS + sentence-transformers: higher semantic recall, requires GPU, 300ms overhead.
Tradeoff: lower semantic recall → offset by <1ms CPU-only latency
Local Llama 3.2 over Cloud API
→ Chosen: Ollama (PulseOps)
Why
Incident management must work during network outages. Zero external dependencies. Data privacy enforced by architecture, not policy.
Alternative
GPT-4 API: higher accuracy, but unavailable during the exact incidents where it's needed most.
Tradeoff: smaller context, lower accuracy → offset by 100% availability
Langfuse over Custom Logging
→ Chosen: Langfuse + OpenTelemetry
Why
Purpose-built for LLM observability. Token cost tracking, per-trace latency, hallucination eval hooks, and dataset management.
Alternative
Prometheus + custom: requires building the LLM-specific layer from scratch (weeks of effort).
Tradeoff: vendor dependency → massive setup savings, open-source self-hostable
Recall over Accuracy (Clinical ML)
→ Chosen: Domain-constrained loss function
Why
In medical diagnostics, a False Negative (missed disease) is categorically worse than a False Positive (unnecessary test). Standard Accuracy is the wrong objective function for this domain.
Alternative
Optimizing for F1/Accuracy: maximizes overall performance, hides catastrophic False Negative rate on imbalanced data.
Tradeoff: precision -6% → recall +25%, clinically correct, resulted in patent
