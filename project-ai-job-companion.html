The Problem

The modern application pipeline is heavily asymmetrical. Recruiters filter applications using **Applicant Tracking Systems (ATS)** that scan for specific keywords, forcing applicants to spend up to 45 minutes manually tailoring their resume for every single job submission. This process is unscalable, error-prone, and presents severe friction for high-quality candidates.

Building an automated solver requires parsing semi-structured PDFs, conducting multi-step LLM analysis, generating consistent styling schemas, and printing standard-compliant PDFs. Doing this in a single HTTP route triggers timeouts, blocks threads, and fails under normal traffic loads.

Core Engineering Decisions

Celery + Redis vs Blocking FastAPI Routes

The Alternative

Handle API queries, scrape job listings, and query LLM endpoints directly inside the FastAPI route handlers.

The Decision

LLM generation and Headless Chromium PDF rendering take 15–30 seconds. Synchronous processing would tie up web worker threads, leading to gateway timeouts. Offloading the work to Celery queues guarantees the backend remains responsive to user clicks immediately.

Trade-off: Requires maintaining additional infrastructure containers (Redis + Celery workers), but is vital for application stability.

Jinja2 + Headless Chrome vs Native Canvas Libraries

The Alternative

Draw string coordinates, margins, and lines manually using Python libraries like ReportLab.

The Decision

Direct PDF canvas drawing is fragile and doesn't handle dynamic text heights well. By injecting tailored JSON structures into standard semantic HTML templates (using CSS Flexbox/Grid), we leverage Pyppeteer to wait for web fonts and print exact vector-based, selectable PDFs.

Trade-off: Spawning Chromium processes is memory-intensive. Requires strict worker process limitations to avoid server crashes.

Fallback Model Routing (Gemini & Llama 3)

The Alternative

Hardcode a single LLM provider, exposing the application to third-party outages or rate limit barriers.

The Decision

Designed a fallback router. The pipeline uses Gemini 1.5 Flash as the primary agent (optimizing costs and parsing speed on large contexts), with an automatic fallback to Llama 3.3 via OpenRouter in case of rate limits or API outages.

Trade-off: Requires managing slightly different system prompts, but ensures near 100% uptime.

PostgreSQL JSONB Caching

The Alternative

Query the LLM on every page refresh or request, leading to massive token costs and slow load times.

The Decision

Implemented a caching layer in PostgreSQL using JSONB. By hashing the combined content of the resume and job listing, subsequent requests for the same pairing instantly retrieve pre-calculated matches in microseconds.

Trade-off: Slightly larger database footprints, but massive cost and latency savings.

Operational Outcome

Pathlight.ai completely automates resume restructuring. By decoupling the API from background processing, it handles batch job execution safely. The system parses, reviews, restructures, and compiles tailored PDFs, decreasing candidate friction and yielding professional, ATS-optimized deliverables.
