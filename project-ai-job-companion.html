// 01 The Business Context

Modern job applications suffer from massive Applicant Tracking System (ATS) rejection rates due to poor keyword matching. Manually tailoring a resume for every single job description is highly unscalable for the user, resulting in generic applications and low conversion rates.

The goal of Pathlight.ai was to build an autonomous pipeline that scrapes a live job URL, parses the user's base resume, and uses an LLM to generate a pixel-perfect, ATS-compliant PDF tailored precisely to the job requirements.

// 02 The V1 Bottleneck (Failure State)

The naive v1 architecture utilized a synchronous FastAPI endpoint. The client would POST the job URL, and the server would `await` the Apify scraper, `await` the Google Gemini LLM generation, and `await` the WeasyPrint PDF rendering.

This failed immediately in production tests.

LLM generation for a full resume takes 15-20 seconds. Standard frontend hosting providers (like Vercel) terminate HTTP requests after 10 seconds. The synchronous architecture resulted in 504 Gateway Timeouts, dropped connections, and a completely broken user experience.

// 03 The Asynchronous Decoupling

To achieve zero blocking APIs, I had to architect a hard decoupling between the ingestion layer and the processing layer. I introduced a Redis message broker and Celery background workers.

Now, FastAPI simply validates the payload, pushes a task ID to Redis, and immediately returns a 202 Accepted response in under 120ms. The client then polls for completion while the heavy AI generation runs securely in the background.

// 04 Observability & Trade-offs

Decoupling solved the timeout issue, but introduced a new constraint: Blind Spots. If the LLM hallucinates or fails in a background worker, the client simply hangs indefinitely.

To solve this, I integrated Langfuse via OpenTelemetry directly into the Celery pipeline. This provided real-time observability into token costs, latency, and prompt injection attempts, allowing the worker to safely fail and update the database state, which the client could then read and render gracefully.

# Celery Worker Logic with Telemetry
@celery.task(bind=True, max_retries=3)
def generate_resume_task(self, user_id, job_url):
    try:
        # 1. Initialize Langfuse Trace
        trace = langfuse.trace(name="resume_generation", user_id=user_id)
        
        # 2. Extract & Generate
        job_data = apify_client.scrape(job_url)
        llm_output = gemini_client.generate(prompt=build_prompt(job_data))
        
        # 3. Finalize State
        db.update_status(task_id=self.request.id, status="COMPLETED")
        
    except Exception as e:
        trace.update(level="ERROR", status_message=str(e))
        db.update_status(task_id=self.request.id, status="FAILED")
        raise self.retry(exc=e, countdown=60)
