Pathlight.ai

Autonomous ATS-optimized resume tailoring engine. Built to solve the scaling problem of manually rewriting resumes for specific job descriptions.

FastAPI LangGraph Celery Redis Gemini Flash Langfuse
View on GitHub ↗

The Problem

Job applications fail ATS screening not because of candidate quality, but because of keyword mismatch. Tailoring a resume manually for every single application is O(n) human effort that does not scale.

The goal was to build a system that accepts a job URL and a base resume, scrapes the job description, and uses an LLM to produce a tailored, ATS-optimized version without hallucinating fake experience.

Engineering Decisions

Async Queue (Celery + Redis) over Synchronous API

The Failure State (V1)

The initial version of Pathlight was a synchronous FastAPI endpoint. Under load, Gemini's response time exceeded the HTTP timeout threshold, causing 504 Gateway Timeouts. The entire request chain blocked.

The Decision

Introduced Celery and Redis. FastAPI now accepts the request, enqueues a job, and returns a task ID instantly. Workers execute the slow LLM call independently.

Result: 0 blocking API calls. System degrades gracefully under load.

LangGraph over LangChain LCEL

The Problem

Standard LLM chains are linear. If the model hallucinates a fake skill or breaks the JSON schema, a linear chain fails catastrophically.

The Decision

LangGraph models workflows as a state machine. I implemented an "Output Guard" node. If the validation step fails, the graph routes back to the LLM node with the error message to self-correct.

Tradeoff: Steeper learning curve, but drastically improved output reliability.

Implementation Detail: The Async Worker

This is the core Celery task that processes the resume in the background, utilizing exponential backoff for transient LLM API failures.

tasks.py Python 
@celery_app.task(bind=True, max_retries=3, acks_late=True)
def tailor_resume(self, task_id: str, payload: dict):
    try:
        # LangGraph state machine execution
        result = tailoring_graph.invoke({
            "resume": payload["resume"],
            "job_description": payload["jd"]
        })
        
        # Render output and update Redis state
        pdf_path = render_pdf(result["html"])
        redis_client.set(task_id, {"status": "done", "url": pdf_path})
        
    except Exception as exc:
        # Exponential backoff for API rate limits
        redis_client.set(task_id, {"status": "failed"})
        raise self.retry(exc=exc, countdown=2 ** self.request.retries)

Observability & Tracing

I integrated Langfuse to trace every LLM generation. When you are building LLM applications, you cannot rely on console logs. You need to trace input tokens, output tokens, latency per hop, and cost per run. If the prompt begins to degrade, Langfuse provides the exact trace to debug it.
