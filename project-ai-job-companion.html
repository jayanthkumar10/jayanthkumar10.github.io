Pathlight.ai

An autonomous AI agent designed to revolutionize the job application process by dynamically tailoring resumes to specific job descriptions using a containerized, async microservices architecture.

FastAPI Celery + Redis Gemini / OpenRouter PostgreSQL Docker
View Source Code

The Problem

The modern job search is structurally broken. Candidates spend up to 90% of their time manually formatting resumes to bypass stringent Applicant Tracking Systems (ATS). This manual tailoring is essential for getting past automated filters, but it is fundamentally unscalable for human candidates.

Core Engineering Decisions

Celery + Redis vs Blocking API Calls

The Alternative

Make direct, synchronous HTTP calls to the LLM and wait for the resume generation inside the FastAPI route handler.

The Decision

LLM generation and Headless Chrome PDF rendering take 15–30 seconds per resume. Doing this synchronously would block the event loop and trigger HTTP timeouts. Moving this to a Celery worker queue ensures zero blocking API calls and resilient error retries.

Trade-off: Increased infrastructure complexity (requiring a Redis container and separate worker processes) but absolutely mandatory for a production-grade NLP pipeline.

Jinja2 + Headless Chrome vs Native PDF Libraries

The Alternative

Use a library like ReportLab or FPDF to manually draw strings and rectangles onto a PDF canvas.

The Decision

PDF generation is famously brittle. By injecting the LLM's JSON output into semantic Jinja2 HTML templates, we leverage standard web technologies (CSS Grid, Flexbox, Web Fonts). We then spawn Headless Chromium via Pyppeteer to perfectly render the HTML to a PDF.

Trade-off: Headless Chrome is extremely memory-intensive. In a high-throughput environment, this requires careful container scaling to prevent OOM kills.

Multi-Model LLM Routing

The Alternative

Hardcode OpenAI or a single model API, making the system vulnerable to outages.

The Decision

Implemented a routing layer. Primary intelligence uses Gemini 1.5 Flash (for extreme speed and cost efficiency on long contexts), with a fallback to OpenRouter (Llama 3) if Gemini is rate-limited or throws 500s.

Trade-off: Requires maintaining multiple prompt structures, but guarantees system uptime during external outages.

PostgreSQL vs Document DB

The Alternative

Use MongoDB to loosely store unstructured job descriptions and raw resume data.

The Decision

We opted for PostgreSQL using JSONB columns. This provides the strict schema validation of relational tables (for user data and job statuses) while still allowing flexible unstructured storage for raw parsed resumes, all within a single managed instance.

Trade-off: Querying deeply nested JSONB can be slightly slower than native NoSQL, but it avoids the overhead of managing two distinct database engines.

Result

Pathlight successfully reduces a 45-minute manual resume tailoring session down to a 30-second automated background task. The architecture is fully containerized with Docker Compose, separating the PostgreSQL state, Redis broker, FastAPI gateway, and Celery workers for an enterprise-ready topology.
