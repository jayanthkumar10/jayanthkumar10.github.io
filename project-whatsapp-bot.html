WhatsApp Booking Bot

A decoupled automation pipeline connecting WhatsApp to Google Calendar using n8n visual orchestration to eliminate manual scheduling effort.

n8n Node.js WhatsApp Cloud API Google Calendar API
Private Repository

The Problem

A small business was spending several hours per week manually reading WhatsApp messages and creating Calendar events. Every time a new booking scenario appeared (e.g., cancellation, reschedule, specific service request), it required a developer to write new regex parsing logic in a monolithic Node.js handler.

This was tightly coupled, brittle, and unmaintainable. I needed a way to decouple the webhook ingestion from the business logic so the flow could be modified quickly.

Decoupled Architecture

sequenceDiagram participant U as User (WhatsApp) participant W as WhatsApp Webhook participant N as Node.js (Auth Layer) participant E as n8n Engine participant C as Google Calendar API U->>W: "Book a slot for tomorrow" W->>N: POST /webhook (HMAC signature) N->>N: Verify Signature N->>E: POST /n8n-webhook (Validated payload) E->>E: Switch Node (Detect Intent) E->>C: GET /freeBusy C-->>E: Available slots array E->>W: Send API message W-->>U: "Available: 10 AM or 2 PM?"

Engineering Decisions

n8n over Node.js for Business Logic

The Alternative

Keep expanding the Node.js server to handle every possible chat intent with massive switch statements and regex parsers.

The Decision

I moved all routing logic into n8n. The Node.js server now acts only as a security layer to verify the WhatsApp HMAC signature. New intents (like "Cancel") are simply added as visual nodes in n8n—requiring zero code deployments.

Trade-off: n8n introduces an extra network hop (~50ms). For a chat bot, this latency is imperceptible. If this were high-frequency trading, this would be the wrong choice. Latency tolerance is context-dependent.

The Outcome

Standard booking flows (checking availability, confirming a slot, sending the confirmation) now run fully automatically. Estimated 70% reduction in manual scheduling effort for the client. The system design ensures that when the client needs to change their availability logic, it can be done visually in n8n in minutes, rather than requiring a code review and server redeployment.
