The Problem

SRE teams deal with alert fatigue. Large volumes of alerts require manual classification, context gathering, and routing. Furthermore, incident data is often sensitive and cannot be sent to public cloud LLM APIs.

The goal was to architect a pipeline that could ingest an alert, parse it, retrieve similar historical incidents, and route it to the correct team—running 100% locally without network dependencies on OpenAI or Anthropic.

Engineering Decisions

TF-IDF over Dense Embeddings (FAISS)

The Context

Standard RAG tutorials default to dense embeddings (OpenAI, Sentence Transformers) and vector DBs like FAISS or Pinecone.

The Decision

IT incidents are highly keyword-dense. Terms like OOMKilled, Error 137, or specific pod hashes are exact-match identifiers. Semantic similarity often misses these. I implemented a custom TF-IDF (sparse) retrieval engine using NumPy.

Result: Higher precision for exact log matches, zero GPU requirement, sub-millisecond local latency.

Llama 3.2 via Ollama over GPT-4

The Context

GPT-4 is the easiest way to build agents, but sending internal server logs and incident details to a cloud provider is a non-starter for many enterprise security teams.

The Decision

I constrained the architecture to use local inference via Ollama. This required aggressive prompt tuning and forcing JSON structured outputs, as smaller models (8B params) struggle with complex reasoning chains.

Result: 100% offline execution. The trade-off is reduced reasoning depth compared to frontier models.

Implementation Detail: Sparse Retrieval

Building the retrieval engine required vectorizing the knowledge base and computing cosine similarity manually, avoiding the overhead of a dedicated Vector DB for a problem space that didn't need it.

retrieval.py Python 
import numpy as np
from sklearn.feature_extraction.text import TfidfVectorizer

class IncidentRetriever:
    def __init__(self, corpus):
        self.vectorizer = TfidfVectorizer(stop_words='english', max_df=0.8)
        self.kb_matrix = self.vectorizer.fit_transform(corpus)
        self.corpus = corpus

    def search(self, query: str, top_k: int = 3):
        # Sparse vector multiplication for exact keyword matching
        query_vec = self.vectorizer.transform([query])
        similarities = (self.kb_matrix * query_vec.T).toarray().flatten()
        
        top_indices = np.argsort(similarities)[-top_k:][::-1]
        return [self.corpus[i] for i in top_indices if similarities[i] > 0.1]
