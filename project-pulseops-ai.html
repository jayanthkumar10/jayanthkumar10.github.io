// 01 The Business Context

Site Reliability Engineering (SRE) teams suffer from severe alert fatigue. When a cascade failure happens, monitoring tools trigger hundreds of redundant emails and PagerDuty alerts, burying the actual root cause in noise.

The objective for PulseOps was to build an autonomous pipeline that parses incoming alerts, triages them against historical incidents, and provides on-call engineers with immediate, actionable context before they even open their laptops at 3 AM.

// 02 The V1 Bottleneck (Cloud Dependency)

Initially, I relied on OpenAI's embedding API and GPT-4 to parse the alerts. This was an architectural mistake.

During an "alert storm" (e.g., 500 emails arriving in a 2-minute window), hitting a cloud API caused massive rate-limiting and latency spikes. More critically, if the incident causing the alerts was a localized network partition, PulseOps itself would lose connection to OpenAI and fail silently exactly when it was needed most.

// 03 The Offline Air-Gapped Pipeline

An Incident Management tool must be more reliable than the systems it monitors. I completely stripped out all cloud dependencies.

I migrated the parsing engine to a quantized, locally-hosted `llama3.2` model running via Ollama. For the historical lookup, I bypassed heavy Vector Databases (like Pinecone) entirely. Instead, I engineered a highly optimized, in-memory TF-IDF (Term Frequency-Inverse Document Frequency) algorithm. This traded a tiny fraction of semantic nuance for 0ms network latency and 100% offline availability.

// 04 The Mathematical Trade-off

Using Deep Learning embeddings (like BERT) to match historical tickets provides the best semantic accuracy, but requires GPU compute and significant memory overhead.

Since SRE incident descriptions are highly specific, keyword-dense text (e.g., `OOMKilled`, `502 Bad Gateway`), a sparse vector approach like TF-IDF actually outperforms dense embeddings by heavily weighting rare, anomalous keywords. I wrote the algorithm from scratch in Python using `numpy` to ensure it ran entirely on CPU without blocking the main event loop.

# In-Memory Incident Matching (Zero API Calls)
def tf_idf_cosine_similarity(query, docs):
    # 1. Corpus tokenization & unique term extraction
    corpus = [query] + docs
    vocab = list(set(word for doc in corpus for word in doc.split()))
    
    # 2. Sparse Vectorization (O(N*M) complexity)
    tf = [[doc.split().count(word) / len(doc.split()) for word in vocab] for doc in corpus]
    idf = [math.log(len(corpus) / sum(1 for doc in corpus if word in doc.split())) for word in vocab]
    
    # 3. Fast matrix multiplication
    tfidf = [[tf_val * idf_val for tf_val, idf_val in zip(doc, idf)] for doc in tf]
    query_vec = tfidf[0]
    
    # 4. Cosine Similarity prioritization
    similarities = []
    for doc_vec in tfidf[1:]:
        dot_product = sum(a * b for a, b in zip(query_vec, doc_vec))
        norm = (math.sqrt(sum(a**2 for a in query_vec)) * math.sqrt(sum(b**2 in doc_vec)))
        similarities.append(dot_product / norm if norm > 0 else 0)
        
    return similarities
