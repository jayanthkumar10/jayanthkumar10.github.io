The Problem

Site Reliability Engineering (SRE) teams operate under severe alert fatigue. During database outages or server drops, raw emails and logs flood inboxes. Engineers spend valuable Mean Time To Resolution (MTTR) identifying the server, diagnosing severity, looking up standard runbooks, and assigning tasks manually.

Using cloud LLM models poses severe security risks, as logs contain sensitive IP addresses, keys, and internal system names. Furthermore, if the network itself goes down, calling cloud APIs becomes impossible. Triaging must happen locally and reliably under extreme hardware load.

Core Engineering Decisions

Local LLM (Ollama) vs Cloud APIs

The Alternative

Use GPT-4 or Claude APIs to analyze incoming server diagnostic alert streams.

The Decision

To protect system topologies and sensitive credentials, running local inferences is critical. Running Llama 3.2 locally using Ollama guarantees 100% data sovereignty. It also ensures the triage runner remains fully functional even during severe external network outages.

Trade-off: Local models require dedicated host memory resources and are less conversational, requiring highly structured prompt JSON instructions.

Custom In-Memory TF-IDF vs Heavy Vector Databases

The Alternative

Deploy external databases like ChromaDB or Pinecone to run vector search for historical incidents.

The Decision

Under heavy alert storms, generating model embeddings for hundreds of logs risks GPU OOM crashes and high latency. I built an in-memory sparse retrieval engine calculating TF-IDF cosine similarity. It runs in microseconds on standard CPU configurations without network overhead.

Trade-off: Keyword matching does not capture semantic synonyms as deeply as embeddings, but is significantly faster and less prone to failures.

Operational Outcome

PulseOps AI isolates noise and speeds up triage. By structuring log diagnostics, querying previous RCAs, and routing the incident to the appropriate engineer based on skills and workload, it significantly decreases SRE overhead and limits SLA breach risks.
