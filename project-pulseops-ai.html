PulseOps AI

An autonomous incident response system for SRE teams. It utilizes a chained multi-agent supervisor architecture backed by a local Llama 3.2 engine to triage server alerts with zero external network dependency.

Python FastAPI Local Llama 3.2 TF-IDF Memory

The Problem

Site Reliability Engineering (SRE) teams suffer from severe alert fatigue. When an unstructured alarm email arrives at 3 AM, engineers waste precious Mean Time To Resolution (MTTR) just reading the alert, parsing the severity, and manually searching runbooks to find similar historical incidents.

Chained Multi-Agent Architecture

Core Engineering Decisions

Local LLM (Ollama) vs Cloud API

The Alternative

Use OpenAI GPT-4 or Anthropic Claude for parsing unstructured logs.

The Decision

IT infrastructure alerts contain highly sensitive server topologies and IP addresses. Furthermore, if the network itself is degraded (causing the alert), a Cloud API call will fail. Running `llama3.2` locally via Ollama ensures 100% offline availability and complete data sovereignty.

Trade-off: Local LLMs require significant host compute (RAM/GPU) and are generally less capable at complex reasoning than frontier models, requiring us to split the workflow into simpler, highly constrained multi-agent steps.

Custom TF-IDF Vector Database vs Pinecone/Chroma

The Alternative

Deploy a heavy vector database (like ChromaDB) or use a SaaS vector store (Pinecone) to search historical incident runbooks.

The Decision

During a severe outage, alert floods can cause heavy HTTP timeouts or GPU OOM (Out Of Memory) errors when embedding hundreds of logs. I implemented a custom In-Memory TF-IDF cosine similarity search. It requires zero GPU, zero network calls, and executes in microseconds.

Trade-off: TF-IDF is sparse retrieval (keyword matching) rather than dense semantic matching. It won't understand synonyms as well as an LLM embedding, but it is infinitely faster and more stable under extreme load.

The Outcome

PulseOps AI acts as a reliable layer between noisy alerts and exhausted engineers. By automatically triaging, fetching the historical Root Cause Analysis (RCA), and assigning the ticket based on real-time engineer workloads, the system drastically reduces the initial friction of incident response.
